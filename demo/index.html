Predicate-grounded scientific database construction

From open-ended scientific questions to auditable database entries.

DB-Curator builds a topic-conditioned literature set, discovers candidate compounds, and verifies each entry against user-defined predicates before release.

Run toy pipeline See how it works

This web demo is intentionally lightweight. It demonstrates the control flow and interaction model in the browser; production runs use LLM agents, literature APIs, local full-text corpora, chemical grounding, and provenance checks.

Core idea

Dynamic literature construction + predicate-state verification

Instead of asking an LLM to simply list plausible compounds, DB-Curator treats every candidate as an evidence contract: required predicates must be supported, exclusion predicates must not be triggered, and unresolved predicates drive follow-up retrieval.

Clarify the database scope

The user request is converted into a machine-actionable rubric with mandatory inclusion criteria and exclusion rules.

02

Construct literature dynamically

Broad topic searches, inspected results, candidate identities, and critique feedback all add evidence to the working corpus.

03

Discover and ground candidates

Chemical mentions are normalized, ranked, and filtered before expensive entry-level verification.

04

Verify before release

A Researcher-Critique loop checks candidate claims against paper context and leaves weak cases evidence-limited.
